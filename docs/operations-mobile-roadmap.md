# 호스팅 매니저 모바일 앱과 현장 기록 개선 계획

2026년 10월 2일 사용자와 논의한 개선 방향을 다음 작업에서도 참고하도록 기록한다. 사용자는 앱 개선 방향을 기억해 달라고 요청한 뒤, 직원이 웹앱에서 직접 기록하도록 UX 개선을 승인했다. 현장 빠른 기록 화면과 재고 저장 기능을 개발했으며, 운영 배포와 신규 재고 테이블 적용은 아직 진행하지 않았다.

## 합의한 앱 개선 방향

기존 관리자 웹을 활용하는 설치형 웹앱 PWA를 먼저 완성한다. 관리자와 청소 담당자가 홈 화면에서 업무를 열고, 필요한 알림을 눌러 해당 작업으로 바로 이동할 수 있게 한다.

1. 관리자 화면에도 홈 화면 설치 안내를 제공한다. 현재 설치 안내와 서비스 워커 등록은 청소 화면에 연결되어 있다.
2. 청소 배정과 취소, 재배정, 관리자 판단이 필요한 고객 문의에 업무 알림을 적용한다. 이미 AI가 처리한 문의와 중요하지 않은 알림은 줄인다.
3. 알림을 누르면 해당 예약, 청소 작업 또는 대화로 이동한다. 로그인 만료 시 로그인 후 원래 업무로 돌아온다.
4. 현장에서 작성 중인 메모와 사진을 임시 저장하고 연결이 돌아오면 업로드할 수 있게 한다. 실제 저장 결과를 별도로 보여준다.

앱 이름, 아이콘, 독립 실행 설정은 현재 구현되어 있다. 실제 웹 푸시와 오프라인 업무 저장은 아직 구현되지 않았다. 푸시 권한, 개인별 수신 설정, 중복 방지와 계정 전환 처리는 [청소 알림 계획](cleaning-push-plan.md)을 따른다. 앱 설치만으로 서버나 데이터베이스의 조회 지연이 해결되는 것은 아니다.

## 현재 카카오톡 현장 기록의 의미

사용자는 숙소별로 카카오톡 단체방에 깨끗한 재고, 세탁 보낸 수량, 필요한 비품을 함께 기록한다. 사용자가 제공한 안온재 샘플에서 **세탁 제목 위 목록은 숙소에 남은 깨끗한 재고 수량**이라고 확인했다.

| 구분 | 안온재 샘플 | 기록 의미 |
| --- | --- | --- |
| 깨끗한 현재 재고 | 손수건 1, 대형 수건 3, 작은 수건 1, 발수건 2, 베게커버 3, 이불커버 4, 매트커버 1, 방수커버 2, 쿠션 커버 2 | 관측 시점의 보유 수량 |
| 세탁 출고 | 이불커버 3, 매트커버 3, 베게커버 5, 큰수건 5, 작은수건 2, 발매트 1 | 세탁 보낸 품목과 수량 |
| 필요한 비품 | 생수 | 수량이 적혀 있지 않은 요청 |

현재 세탁 기능은 출고와 누적 입고, 미입고, 파손, 재세탁, 작업 이력을 관리한다. 비품 요청과 지급 상태도 관리한다. 이번 개선에서는 숙소별 깨끗한 보유 재고 모델과 직원용 직접 입력 화면을 추가했다. 카카오톡 원문을 해석하는 입력 기능은 후속 검토 사항이다.

## 구현한 빠른 기록 방식

직원이 **숙소 선택 → 기록 종류 선택 → 내용 입력 → 확인 후 저장**하는 방식이다. 재고와 세탁은 품목별 수량을 입력하고, 비품 요청은 사용자가 선택한 자유 텍스트 방식으로 기록한다. 청소 화면의 기록 탭(`/cleaner/records`)과 관리자 재고·세탁 기록(`/admin/inventory`)에서 현재 재고, 세탁 보냄, 세탁 입고, 비품 요청을 처리한다. 청소 오늘 화면에서도 숙소별 기록으로 바로 이동한다. 기존 세탁 일정과 비품 요청 내역은 유지한다.

입력 초안은 기기에서 계정·숙소·기록 종류별로 보관한다. 초안 보관과 서버 저장 완료를 구분한다. 개발 전용 `/admin/inventory/preview`, `/cleaner/records/preview`는 가상 자료만 사용하며 실제 기록을 변경하지 않는다. 카카오톡 붙여넣기와 공유 요약은 후속 개선으로 남긴다.

- 현재 재고는 실사 수량이다. 세탁 출고 수량을 같은 재고 보고에서 다시 차감하지 않는다. 출고 전인지 후인지 불분명한 기록은 사용자가 확인한다.
- 목록에 없는 품목은 0으로 취급하지 않는다. 부분 재고 확인과 전체 재고 확인을 구분하고, 품목별 마지막 확인 시각을 표시한다.
- 세탁 중인 수량과 바로 사용할 수 있는 깨끗한 재고를 구분한다. 출고와 입고는 현재 재고를 자동 증감하지 않는다. 입고 후 깨끗한 총수량은 재고 화면에서 확인한다.
- 품목 이름의 띄어쓰기와 오타는 정리한다. 큰수건과 대형 수건, 발수건과 발매트처럼 같은 품목인지 불명확한 표현은 확인 후 숙소별 품목 이름에 연결한다.
- 비품 요청은 “생수 부족\n쓰레기봉투 20L 한 묶음 필요”처럼 자유롭게 적는다. 품목·수량·단위 선택을 강제하지 않고, 입력한 문장과 줄바꿈을 보존한다. 원문을 수량 목록으로 자동 해석하거나 임의로 1개를 저장하지 않는다. 최대 2,000자이며 긴급 여부를 선택할 수 있다.
- 같은 원문을 반복해서 붙여넣거나 저장을 재시도해도 중복 출고와 중복 요청이 생기지 않게 한다. 서로 다른 날의 동일 수량 보고는 같은 기록으로 합치지 않는다.
- 비품 요청은 기존 SupplyRequest 흐름에 연결한다. 요청자·숙소·원문과 승인·거절·지급 완료 상태를 함께 관리하고, 이전 품목형 내역도 계속 표시한다. 텍스트는 기존 JSON 필드를 활용하므로 별도 DB 변경이 필요 없다. 같은 요청을 달력용 SupplyTodo에도 자동으로 중복 생성하지 않는다.
- 빠른 세탁 보냄 기록은 품목과 보낸 수량만 입력하며 메모는 선택 사항이다. 사용자는 업체 이름, 보낸 날짜, 배송 예정일 입력을 생략하도록 요청했다. 기록 시각과 한국 기준 기록일은 서버에서 자동으로 남기되, 실제 출고일을 확인한 값으로 표시하지 않는다. 업체와 배송 예정일은 미정으로 보관하고 임의의 업체나 날짜를 넣지 않는다. 예정일 미정 건은 진행 중·입고 대기에 포함하며 배송 지연으로 판정하지 않는다. 기존 수거 일정 등록과 예정일 수정은 세탁 관리에서 처리한다.
- 카카오톡 공유 요약 복사는 후속 검토 사항이다. 실제 단체방에 자동 발송하는 기능은 이번 요청 범위에 없다.

숙소별 최소 재고를 별도로 설정하면 부족 품목과 보충 필요 수량을 표시할 수 있다. 아직 기준 수량이 정해지지 않은 품목은 부족 여부를 단정하지 않는다.

## 카카오톡 연결 범위

공개 카카오톡 메시지 API는 발송 기능을 제공하며 기존 일반 단체방 대화 내용을 읽어오는 API는 확인되지 않았다. 일반 단체방의 자동 수집을 전제로 개발하지 않는다. 첫 단계는 직원이 웹앱에 직접 기록하는 방식이다. 카카오톡 채널의 일대일 챗봇에 직원이 기록을 보내는 방식은 별도 연결과 개발을 검토할 수 있으며 기존 단체방 수집과는 다르다.

공식 근거: [카카오톡 메시지 API](https://developers.kakao.com/docs/ko/kakaotalk-message/common), [채팅 내용 조회에 대한 카카오 답변](https://devtalk.kakao.com/t/api/135418), [카카오톡 채널 챗봇 연결](https://kakaobusiness.gitbook.io/main/tool/chatbot/tutorial/make_chatbot/tutorial_1).
