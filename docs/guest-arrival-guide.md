# 게스트 도착 안내 / 픽업 요청

별하재·안온재·운와당·화연재용 공개 안내 페이지입니다. 로그인 없이 숙소 안내, 인천공항 픽업 요청, 기존 투어 상품을 확인합니다.

- 영어 기본: `/guest/byulha`
- 언어: `?lang=ko` 한국어, `?lang=en` 영어, `?lang=zh` 중국어(간체), `?lang=ja` 일본어. `zh-CN`과 `zh-Hans`도 중국어로 열립니다.
- 관리자: `/admin/guest-services` (사이드바의 **게스트 픽업 요청**)
- 추가 숙소: `/guest/anon`, `/guest/unwadang`, `/guest/hwayeonjae`. 각각 `?lang=ko`를 붙이면 한국어로 열립니다.
- `/guest`는 별하재 안내로 이동합니다. 관리자에서 공유할 숙소와 언어를 선택해 안내 페이지를 열거나 링크를 복사할 수 있습니다.
- 추가 세 숙소의 주소는 기존 숙소 지식 자료에서 공개 주소만 옮겼으며, 체크인·체크아웃과 사진은 공개 숙소 메타데이터를 사용합니다.
- 사용자 확인에 따라 네 숙소 모두 픽업 기준 요금은 100,000원입니다. 안온재·운와당·화연재의 짐 보관은 담당자 문의로 안내합니다.
- 주차는 네 숙소 모두 푸른기린(화동 58-1), 정독도서관, 현대미술관, 현대빌딩 또는 모두의주차장 안내를 사용합니다. 현대빌딩이 안내한 선택지 중 가장 저렴하되 이용 시간·정책에 따라 달라질 수 있으며, 요금·운영시간·빈자리·예약은 주차장 또는 앱에서 확인하도록 안내합니다. 전용·무료 주차를 제공한다고 표시하지 않습니다.
- 페이지 본문, 폼, 접수 결과, 오류와 기존 인력거 투어 3개 카드가 네 언어를 지원합니다. 기존 투어 상세·예약 페이지의 언어 기능은 이번 변경 대상이 아니며, 새로 등록되는 상품에 번역이 없으면 원문을 표시합니다.
- 픽업 요청에 선택한 언어를 저장하고 관리자에게 표시합니다. 기존 language 컬럼은 TEXT이므로 언어 추가용 DB 변경은 없습니다.
- 이번 숙소 추가에는 새 DB 변경이 없습니다. 기존 픽업 요청 테이블 생성 SQL을 실행했다면 다시 실행하지 않습니다.

## 운영 DB와 Netlify 적용 순서

1. Supabase SQL Editor에서 `prisma/migrations/20260918000000_guest_service_requests/migration.sql` **전체를 한 번 실행**합니다. 기존 직원 통합 SQL을 다시 실행하지 않습니다.
2. 새 테이블 `public.guest_service_requests`가 생성된 것을 확인합니다. 사용자/청소/기존 예약 데이터는 변경하지 않습니다.
3. 변경 코드를 Netlify에 연결된 브랜치에 반영해 자동 배포합니다. 현재 빌드의 Prisma generate는 DB 테이블을 생성하지 않으므로 1번이 필요합니다.
4. 로그인 후 관리자 메뉴가 열리는지 확인하고, 게스트 안내 페이지의 투어 목록 및 픽업 요청 접수를 확인합니다.
5. 배포 완료 후 공유 주소: `https://voidanchae.com/guest/byulha?lang=ko` 또는 영어용 `/guest/byulha`.

SQL은 한 DO 문으로 구성되어 있으며 재실행용이 아닙니다. 이미 테이블이 있으면 추가 실행하지 않습니다. 앱 서버 DB 계정은 기존 Prisma와 같이 테이블 소유자 또는 RLS를 우회할 수 있는 서버 전용 계정을 사용합니다. 브라우저의 anon/authenticated 역할에는 직접 조회 권한을 주지 않습니다.

## 운영 방법

- 상태는 접수 → 확인 중 → 확정, 또는 취소입니다. 취소한 요청을 다시 활성화하지 않습니다.
- 담당자가 차량, 인원/수하물, 최종 요금을 확인하고 고객에게 별도 연락한 뒤 확정합니다. 확정에는 내부 메모가 필요합니다.
- 기준 요금은 사용자가 제공한 인천공항 밴택시 100,000원입니다. 결제, 자동 배차, 알림톡/이메일 발송은 포함하지 않습니다.
- 관리자 화면은 관리자 전체/매니저 담당 숙소 범위를 적용합니다. 청소담당자는 조회·수정할 수 없습니다.
- 동일 요청 재시도는 같은 접수 번호로 처리합니다. 동시 수정은 버전 충돌로 막습니다.
- 투어는 기존 활성 상품을 최대 3개 보여주고 기존 상세·예약 화면으로 연결합니다. 기존 투어 예약/전달 기능은 이번 변경 범위가 아닙니다.
- 이름, 연락처, 항공편 등을 보관하므로 내부 메모에 결제 정보나 여권번호를 넣지 않습니다. 영구 삭제 및 자동 보관 기간 정리는 이번 버전에 포함되지 않았습니다.

## 확인 결과

- 픽업 API/권한/중복 요청/상태 변경 및 PostgreSQL 마이그레이션 테스트 포함.
- 실제 운영 DB에 대한 마이그레이션·접수·메시지 전송은 개발 검증에서 수행하지 않았습니다.
- 개발 미리보기에서 DB 네트워크 접근이 제한되면 투어 영역은 오류와 재시도 버튼을 표시합니다.
