# 외부 API와 공개 서비스 권한

외부 API 키는 발급된 scope와 지점 목록을 기준으로 사용한다. 기존의 빈 지점 목록은 전체 지점 설정으로 유지하지만, 매 요청에서 현재 사업자 상태와 지점·사업자 기능을 확인하여 실제 허용 지점을 해석한다. 해석 결과가 빈 배열이면 접근 가능한 지점이 없으며 전체 접근으로 되돌아가지 않는다. 사업자 소속을 키 이름이나 발급자 정보에서 자동 추측하지 않는다.

외부 청소·예약·지점 조회는 각각 청소·예약·숙소 관리 기능과 채널 연동 기능을 필요로 한다. 사용 중지한 사업자나 꺼진 기능의 지점은 응답에서 제외하고 생성·변경·삭제를 거절한다. 공개 예약 가격·달력도 예약과 연동 옵션을 확인하며, iCal 동기화는 원격 조회 전에 연동 상태를 확인한다. 객실 패드 체크아웃은 게스트 서비스 옵션이 필요하다.

신규 외부 청소의 `externalSource`는 `api-client:{client.id}`이다. 이름이 비슷한 다른 고객의 청소 ID가 충돌하지 않는다. 동일 source/외부 ID는 같은 지점에서만 갱신하며 다른 지점으로 이동할 수 없다. 같은 지점·날짜의 다른 일정은 충돌로 거절한다. 변경과 활동 기록은 하나의 트랜잭션으로 저장한다.

기존 이름의 첫 단어로 기록된 source는 자동 변경하지 않는다. 해당 legacy source와 지점에 접근하는 API client가 정확히 하나일 때 기존 client의 기록으로 인정한다. 회수된 client도 역사적 소유권 검사에 포함한다. 여러 client가 겹치는 경우 기존 기록을 임의로 넘기지 않고 `legacy_source_ambiguous` 또는 `not_your_cleaning`으로 거절하므로 실제 소유 client를 확인하여 별도 정리해야 한다.

같은 사업자나 파트너의 다른 client를 생성했다고 기존 client의 기록을 자동 소유하지 않는다. 새 client 발급·기존 키 회수 시 기존 source 소유권 이전 여부를 함께 확인해야 한다. 이 변경에 새로운 테이블·컬럼이나 운영 데이터 자동 수정은 없다.
