# 직원 관리 통합

## 화면

- `/admin/staff`: 관리자·매니저·청소 담당자 통합 목록, 역할 필터 및 이름/연락처/이메일 검색.
- `/admin/users`, `/admin/cleaners`: 통합 화면으로 리다이렉트.
- 관리자에게 전체 직원, 매니저에게 자신이 소유한 청소 담당자만 표시한다. 청소 담당자는 직원 관리에 접근할 수 없다.
- User와 Cleaner가 userId로 연결되어 있으면 한 명으로 표시한다. 계정 없이 링크만 쓰는 청소 담당자도 포함한다. 전화번호로 자동 병합하지 않는다.
- 직원 등록에서 역할을 선택한다. 관리자·매니저는 이메일/비밀번호, 청소 담당자는 선택적으로 전화번호 로그인 계정을 함께 만든다.
- 직원 상세: 기본 정보 / 담당 숙소 / 로그인 / 알림. 초대·가입 승인 기능은 별도 패널에서 유지한다.
- 삭제 대신 로그인 중지와 배정 해제로 업무를 중단할 수 있다. 기존 청소 일정·이력은 보존한다. 로그인 중지는 개인 일정 링크를 폐기하지 않으며 링크는 따로 재발급할 수 있다.

## 저장 및 권한

기존 User, Cleaner, UserProperty, CleanerProperty와 ID를 그대로 유지한다. 새 로그인 없는 청소 직원은 Cleaner만 생성한다. 앱 로그인 사용 시 User와 Cleaner를 한 트랜잭션에서 연결한다. 비밀번호는 무작위 초기 비밀번호로 생성하고 bcrypt로 저장하며 생성/재발급 응답에서 한 번만 표시한다. 기존 계정 비밀번호는 마이그레이션으로 변경하지 않는다.

기본 정보 수정은 연결된 계정과 프로필을 한 트랜잭션으로 갱신한다. 휴대폰 변경 시 전화번호 로그인 식별자만 갱신하고 비밀번호와 실제 이메일은 보존한다. 기존 계정과 전화번호가 충돌하면 자동으로 계정을 가져오거나 병합하지 않는다.

관리자는 모든 직원을 관리한다. 매니저는 기존 ownerId 기준으로 자신의 청소 담당자만 관리하며 선택 배정은 자신의 숙소 접근 범위 안에서만 할 수 있다. 청소 담당자의 예약/상담 권한을 추가하지 않는다. 고객 문의 알림은 기존 관리자·매니저 수신자 규칙을 유지한다.

## 숙소 배정

- 전체: 청소 담당자를 소유한 운영자(ownerId)의 전체 숙소. 관리자 계정의 전체 사이트 권한과 다르다.
- 선택: CleanerProperty에 선택한 숙소를 저장한다. 빈 선택은 거부한다.
- 없음: `Cleaner.noProperties = true`. 새 청소 조회·신청 범위와 오픈 알림에서 제외한다. 기존 배정 청소 일정과 이력은 삭제하지 않는다.

이전 API의 mode 없는 빈 propertyIds 요청은 기존 전체 동작을 유지한다. 통합 화면은 mode를 반드시 명시한다. 기존 명시적 배정과 전체 숙소 권한은 마이그레이션으로 바뀌지 않는다.

## 배포

`prisma/migrations/20260915020000_staff_scope/migration.sql`을 코드 배포 전에 적용한다. cleaners 테이블에 no_properties BOOLEAN NOT NULL DEFAULT false 열 하나를 추가한다. 기존 데이터를 삭제하거나 병합하지 않는다. 기존 문의 자동답변 관련 마이그레이션과는 별개다.
