# 게스트 모바일 웹앱

게스트는 설치 없이 `/stay/{숙소 슬러그}`에서 객실 안내, 투어·택시 요청, 숙소 문의, 요청 처리 상태를 이용합니다. `/stay/preview`는 실제 접수 없이 살펴보는 샘플입니다.

## 운영 순서

1. 관리자 → 게스트 신청함 → 숙소 QR에서 고정 QR을 확인합니다.
2. 객실에 고정 QR을 비치하거나 링크를 전달합니다. 게스트는 현재 투숙 예약에 등록된 전체 이름만 입력하며 영문 대소문자는 구분하지 않습니다. 별도 이용 코드 발급·입력은 없습니다.
3. 패드 연결 탭에서 일회용 연결 코드를 발급한 후 웰컴패드 관리자 화면에 입력합니다. 연결된 패드는 서버가 확인한 현재 투숙 예약의 QR을 표시합니다.
4. 신청함에서 요청 내용을 확인하고 처리 상태와 게스트에게 보여줄 안내를 저장합니다. 내부 메모는 직원에게만 보입니다.

투어·택시 접수만으로 예약이나 배차가 확정되지 않습니다. 신청함의 답변은 게스트 앱에서 확인하며, 문자나 Beds24 메시지가 별도로 자동 발송되는 것은 아닙니다. 기존 Beds24 초대장 안에도 게스트 앱 입구가 연결됩니다.

## 접속 범위

고정 객실 QR은 해당 숙소의 현재 투숙 예약과 전체 이름을 대소문자 구분 없이 대조합니다. 체크인 전·체크아웃 후 예약이나 취소된 예약은 로그인할 수 없으며, 여러 현재 예약이 겹치면 임의로 선택하지 않습니다. 직원 계정과 게스트 세션은 분리됩니다. 기존 예약 전용 링크는 도착 전 서비스 계획에도 사용할 수 있습니다. 체크아웃, 예약 취소, 날짜·이름 변경, 패드 연결 해제는 관련 기존 접속을 무효화합니다.

관리자의 휴대폰 연결 해제는 해당 예약의 기존 세션을 종료합니다. 현재 투숙 중인 게스트는 이름으로 다시 로그인할 수 있습니다. 로그인 시도 제한, 숙소 범위 확인, 쿠키와 요청 보호는 유지합니다. 이전 이용 코드의 로그인·발급 API는 더 이상 사용할 수 없으며, 패드 등록용 일회용 연결 코드는 별도로 유지합니다.

객실 안내는 기존 웰컴패드에서 검토한 설명을 일반 텍스트로 옮겼습니다. Wi-Fi는 현재 투숙 예약에만 서버 설정에서 제공하며, 도어락 비밀번호와 관리자용 정보는 전달하지 않습니다. 설명이 없는 지점은 공통 수칙만 표시합니다.

## 배포

호스팅 매니저의 새 소스와 웰컴패드의 새 연결 파일을 각각 배포해야 합니다. 데이터 구조는 `prisma/migrations/20261002140000_guest_stays/migration.sql`입니다. `node scripts/guest-stay-schema.mjs`로 읽기 전용 확인, `--apply`로 이 기능의 다섯 새 테이블만 적용할 수 있습니다. 모든 과거 미적용 마이그레이션을 함께 실행하지 않습니다. 이후 Prisma 클라이언트를 다시 생성합니다.

2026년 10월 5일의 이름 로그인 전환은 기존 테이블을 그대로 사용하며 추가 DB 마이그레이션은 없습니다. 기존 nullable 코드 해시 열은 호환성을 위해 남아 있지만 로그인이나 새 발급에 사용하지 않습니다. 이 문서의 변경이 운영 배포 완료를 뜻하지는 않습니다.

웰컴패드 연결용 서버 주소는 `HOSTING_MANAGER_URL`이며 배포 환경에서 HTTPS 호스팅 매니저 주소를 사용합니다. QR에 표시할 주소인 `GUEST_APP_ORIGIN`도 같은 주소로 맞춥니다. 공통 관리자 API 키를 게스트 브라우저에 전달하지 않습니다. 미연결 패드의 기존 신청 기능은 유지됩니다.
