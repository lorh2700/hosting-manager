# 사업자·역할·기능 설정

`/admin/settings`는 사업자, 사용자 권한, 지점 기능, 지점 추가 요청을 관리하고 `/admin/activity`는 처리 이력을 조회한다.

- 슈퍼매니저(`super_admin`)는 사업자를 등록하고 사업자 관리자를 초대한다. 사업자별 세탁·PriceLabs 등의 사용 옵션과 지점 생성·소속 변경을 관리한다.
- 사업자 관리자(`admin`)는 본인 사업자의 사용자와 지점을 관리한다. 자기 사업자의 매니저·청소 인력만 수정하고 관리자 승격이나 다른 사업자로의 이동은 할 수 없다. 지점 추가는 요청 후 슈퍼매니저 승인을 받는다.
- 매니저(`manager`)는 같은 사업자에 속한 배정 지점에서 배정된 기능을 사용한다. 청소 인력(`cleaner`)은 청소와 재고·세탁·문제·비품 보고 기능만 배정할 수 있다.
- 사용자 메뉴가 `null`이면 역할의 기본 메뉴를 사용하고 `[]`이면 선택 기능을 허용하지 않는다. 사업자 또는 지점에서 꺼진 기능은 사용자 메뉴에 배정해도 사용할 수 없다. 지점 설정으로 사업자 사용 옵션을 다시 켤 수 없다.

설정 변경은 `version`을 보내야 한다. 다른 사용자의 저장으로 버전이 바뀌면 409를 반환한다. 설정 변경과 감사 이력은 같은 트랜잭션으로 저장하며 이력 저장 실패 시 설정도 롤백한다. 로그에는 작업 종류, 대상 ID, 변경 필드 이름만 기록한다. 비밀번호·토큰·고객 메시지·입력 본문은 복사하지 않는다. 감사 이력은 추가만 가능하고 웹에서 수정·삭제하는 기능은 없다.

## 배포 전 데이터베이스 전환

`prisma/migrations/20261004010000_business_access_settings/migration.sql`이 필요하다. 이 작업에서 운영 DB에 실행하지 않았다. Prisma 스키마 검증과 로컬 PostgreSQL(PGlite)의 실제 외래키·권한·경합·감사 롤백을 검증한다. 운영 데이터에 적용하기 전에 백업과 미적용 마이그레이션 목록을 확인한다. 적용한 코드와 데이터베이스를 함께 배포해야 한다. 테이블/컬럼이 없으면 새 설정 API는 503과 `migrationRequired:true`를 반환한다.

마이그레이션은 기존 사용자 역할을 그대로 보존한다. 지정된 플랫폼 운영자만 별도 확인 후 `super_admin`으로 승격한다. 기존 지점과 일반 직원의 사업자는 자동 추측하지 않고 미소속으로 유지한다. 슈퍼매니저는 실제 사업자를 생성한 뒤 지점 소속을 설정한다. 기존 직원·미배정 관리자 함께 이동을 선택하면 사용자의 모든 배정 지점을 옮기는 경우에 한해 지점·사용자·이력을 한 트랜잭션으로 이관한다. 사업자가 지정되지 않은 기존 관리자도 역할을 유지하며 연결할 수 있고, 화면에 대상과 사업자 전체 관리 권한을 안내한다. 슈퍼매니저 계정과 선택 지점에 배정되지 않은 사용자는 함께 이동하지 않는다. 일부 지점만 이동하거나 이미 다른 사업자에 소속된 관리자를 함께 이동하려 하면 저장하지 않는다. 소속 변경 시 기존 청소 공유 링크도 교체된다. 이전 버전의 사업자 없는 관리자 초대는 회수하고 다시 발급한다.

관리자 초대 API는 `/invite/{token}` 링크를 발급한다. 이메일이나 문자 발송은 수행하지 않는다. 같은 이메일로 먼저 가입한 대기 계정도 로그인 후 명시적으로 초대를 수락할 수 있다. 만료된 초대는 재발급·회수할 수 있으며 재발급 시 이전 링크는 무효화한다. 승인된 지점은 ‘준비 중’으로 등록되고, 숙소 설정에서 사진·소개·주소·인원·Beds24 정보를 채운 뒤 공개한다. 공개 목록과 예약 검색은 새 지점도 DB의 공개 상태·사업자 옵션을 기준으로 반영한다. 활동 기록은 이 변경 이후의 작업부터 생성되며 과거 작업을 추정해 만들지 않는다.
