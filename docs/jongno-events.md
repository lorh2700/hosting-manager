# 종로 행사 캘린더

## 화면과 운영 방법

- 공개 캘린더: `/guide/jongno-events`. 북촌 가이드와 투어 메뉴에서 연결한다.
- 관리자: `/admin/jongno-events`. 관리자 계정만 행사와 사진을 등록·수정할 수 있다.
- 서울 숙소의 예약 페이지와 게스트 안내 페이지에는 날짜가 선택되거나 예약에 연결된 경우 투숙 기간의 추천 행사를 최대 3개 표시한다. 이름·예약 번호·초대장 토큰은 행사 링크에 넣지 않는다.
- 한국어와 영어 제목·설명을 입력할 수 있다. 영어 내용이 없는 경우 한국어 원문임을 표시한다. 게스트 안내의 일본어·중국어 사용자는 행사 정보가 영어로 제공됨을 안내한다.

`새 행사`에서 행사명, 분류, 지역, 기간, 장소와 공식 링크를 입력하고 초안으로 저장한다. 사진은 JPEG/PNG/WebP 파일을 최대 6장 등록할 수 있다. 각 파일은 8MB 이하이며 서버에서 최대 1600px WebP로 줄여 저장한다. 첫 사진이 대표 이미지이며 순서, 사진 설명, 출처를 수정할 수 있다. 사진을 폼에서 제거해도 저장소의 원본을 즉시 삭제하지 않는다.

공개 상태는 `초안 / 공개 / 취소`로 구분한다. 초안·취소된 행사는 공개 API에서 제외한다. 공개된 행사도 조회 기간 밖에서는 표시하지 않는다. 실제 휴관 요일·휴관일을 입력하고 회차와 시간, 요금, 예약 조건은 공식 안내로 확인한다. 날짜가 겹친다는 이유만으로 좌석이나 예매 가능 여부를 보장하지 않는다. 서로 다른 관리자가 수정하면 버전 충돌을 알려 기존 내용을 덮어쓰지 않는다.

## 데이터와 설정

예약 데이터의 `Event`와 별도로 `jongno_events` 테이블을 사용한다. 추가 스키마는 `prisma/migrations/20261002020000_jongno_events/migration.sql`이다. 이 SQL은 행사 테이블과 인덱스만 추가하며 기존 예약·청소 테이블을 변경하지 않는다. 새 테이블의 RLS와 공개 DB 역할 권한을 제한하여 초안이 Supabase REST로 노출되지 않도록 한다. 일반적인 신규 배포에는 기존 프로젝트의 마이그레이션 절차를 따르고 Prisma 클라이언트를 생성한다. SQL을 직접 적용하는 환경에서는 적용 여부를 확인한 뒤 이 마이그레이션만 실행한다.

기존 운영 환경에서 이 추가 스키마만 적용할 때는 `node scripts/jongno-events-schema.mjs`로 상태를 확인하고 `--apply`를 추가한다. 이 도구는 예약 테이블이나 다른 미적용 마이그레이션을 실행하지 않는다. Prisma 마이그레이션 이력을 사용하는 환경에서는 직접 SQL 적용 후 해당 마이그레이션을 applied로 정리해야 한다.

사진 저장은 기존 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_STORAGE_BUCKET` 설정을 사용한다. 기본 버킷은 `tour-images`이다. 서비스 키는 서버에만 두며 브라우저에 전달하지 않는다. 일반 행사 링크를 저장하는 것과 달리 사진은 공개용 버킷에 등록한다.

공개 API는 월별 또는 최대 93일 기간으로 조회하고 페이지당 최대 100개를 반환한다. 관리자 목록은 페이지당 최대 50개다. 페이지 이동에 커서를 사용한다. 사진 요청은 관리자 인증 이후 실제 파일 형식과 크기를 검사한다. 사진 압축 과정에서 EXIF/GPS 메타데이터를 제거한다.

## 범위

이번 버전은 관리자가 확인한 행사를 등록하고 공개하는 방식이다. 서울시 문화행사 API와 종로문화플랫폼의 자동 수집, 예약 좌석 연동, 자동 알림 발송은 포함하지 않는다. 행사·이미지 출처는 관리자 화면에 등록할 수 있으며 공개 화면에서 공식 안내로 연결한다.
