# 예약자 이름 로그인 변경 후 점검

2026년 10월 5일. 사용자가 이 대화에서 선택한 anti-slop after 모드로 변경 후 검토했다. 기존 voidanchae 게스트 화면의 색상·서체·레이아웃을 유지하고, 이용 코드 입력·발급을 제거하는 요청 범위만 수정했다. ENERGY 1 / RHYTHM 1 / MOTION 2의 기존 화면 방향을 유지하며 새 시각 효과나 자산은 추가하지 않았다.

## 번호별 결과

1. **HIGH · R-32 · 예약자 이름 입력란의 키보드 포커스 표시 없음**
   - 위치: `app/stay/GuestStay.module.css:60`.
   - 이유: 기존 입력란의 `outline: none` 규칙이 앞선 `:focus-visible` 규칙을 덮는다. 실제 컴포넌트를 렌더링한 브라우저에서 입력란에 키보드로 포커스한 후 `outline-style: none`을 확인했다.
   - 제안: 일반 입력란 규칙의 `outline: none`을 제거해 기존 3px 포커스 표시가 적용되도록 한다.
   - 상태: 이번 변경 전에 존재한 문제이며 감사 결과만 기록했다. After 모드의 “Do not modify anything until the user approves specific numbers” 지침에 따라 이 별도 스타일 변경은 적용하지 않았다.

## 반영한 기능과 확인 범위

- 고정 숙소 QR에서 예약자 전체 이름만으로 현재 투숙 예약을 확인한다. 대문자·소문자·혼합 입력으로 동일 예약이 확인되는 것을 테스트했다. 이름 정규화, 체크아웃 시각, 숙소 범위, CSRF, 서버의 로그인 시도 제한은 유지한다.
- 이용 코드 입력·안내·관리자 발급 UI를 제거했다. 이름 로그인 API는 `code` 필드를 받지 않고, 과거 발급 API는 권한 확인 뒤 410을 반환한다. 패드 등록용 일회성 연결 코드는 별도 기능으로 유지한다.
- 기존 초대장과 예약 전용 링크의 인증을 유지한다. 무효한 링크를 이름 로그인으로 자동 처리하지 않으며, 사용자가 이름 재확인을 선택해야 한다.
- 관리자 휴대폰 연결 해제는 이름·초대장·패드 QR 등 해당 예약의 연결을 종료한다. 현재 투숙객은 예약자 이름으로 다시 로그인할 수 있다. 검토 중 발견한 초대장·패드 경로의 관리자 해제 누락을 수정하고 초대장 경로의 회귀 검사를 추가했다.
- 관련 자동 테스트 37개 통과. 요청 스키마, 대소문자, 숙소·기간 제한, 취소·중복 예약, 시도 제한, 세션 변경, 연결 해제, 기존 초대장, QR 별칭, 객실 안내를 확인했다.
- 실제 `GuestStayApp.tsx`와 모의 API를 이용해 4개 언어 × 320/390/1280px, 총 12개 조합에서 로딩·제출 비활성화·이름만 전송·오류 후 입력 유지·재시도 성공을 확인했다. 가로 넘침과 브라우저 실행 오류는 없었다.
- 새 이름 안내 문구의 대비는 4.9094:1이다. 키보드 포커스 문제는 별도 항목으로 남아 있으므로 전체 접근성 통과를 의미하지 않는다.
- 변경한 UI와 백엔드의 ESLint, TypeScript 검사를 통과했다. 관리자 화면은 타입·린트·API 테스트 범위이며 별도 관리자 브라우저 검사는 하지 않았다.

운영 배포, 실제 게스트 계정 로그인, 실제 객실 패드 검증은 하지 않았다. 운영 반영에는 호스팅 매니저와 객실 패드 양쪽 배포가 필요하다. 이번 이름 로그인 변경에 추가 DB 마이그레이션은 없다.
